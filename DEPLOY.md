# Deploying TalentStream AI

Frontend → **Vercel**. Backend → **Render** (needs websockets for the AI interview).
Database + resume storage → **Supabase**. Redis is optional.

## 1. Supabase
- [ ] Create a project. Turn **off** "Automatically expose new tables" (and the Data API;
      the backend uses Postgres directly and only uses Supabase **Storage**).
- [ ] Storage → create a **private** bucket named `resumes`.
- [ ] Copy: project URL, `service_role` / secret key, and the **Session pooler** connection
      string (Connect → Session pooler, port 5432). Don't use the direct `db.*` host (IPv6 only)
      or the Transaction pooler (breaks asyncpg prepared statements).

## 2. Gemini
- [ ] Create an API key at https://aistudio.google.com/apikey.

## 3. Render (backend)
- [ ] New → Blueprint → pick this repo (it reads `render.yaml`), or create a Web Service with
      root dir `backend`.
- [ ] Set the `sync: false` variables in the dashboard:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Supabase Session pooler string (`postgresql://…`; the app converts it to asyncpg) |
| `GOOGLE_API_KEY` | Gemini key |
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role / secret key |

  `SECRET_KEY` is generated by Render. `FRONTEND_URL` is preset in `render.yaml`; change it if
  your Vercel URL differs.
- [ ] Deploy. `prestart.sh` runs `alembic upgrade head` on every start.
- [ ] Check `https://<service>.onrender.com/ready` → `postgres: ok`.

Free Render services sleep after ~15 min idle (first request takes ~1 min).

## 4. Vercel (frontend)
- [ ] Project settings → Environment Variables → `VITE_API_URL` =
      `https://<service>.onrender.com/api/v1` (Production), then redeploy.

## 5. Smoke test
- [ ] Register, log in, post a job (employer), apply with a PDF (candidate), open the interview.

## Job feed (jobs from other platforms)
The site collects jobs from other platforms' **official APIs** (no scraping) and rates each one for scam signs.
- **Works with no setup:** Remotive and Remote OK (remote jobs). They refresh themselves when someone opens the site
  and a source is more than 6 hours old (their terms ask for at most ~4 fetches a day).
- **For India jobs and walk-in drives:** add a free Adzuna key. Register at https://developer.adzuna.com, then set
  `ADZUNA_APP_ID` and `ADZUNA_APP_KEY` on Render (leave `ADZUNA_COUNTRY=in`). Until then the Walk-in tab will be empty.
  The Adzuna adapter is written from their documented format and hasn't been run against the live API yet, so check
  `/api/v1/feed/stats` after adding the keys (`last_error` shows any problem).
- `INGEST_TOKEN` (generated by Render) lets you force a refresh:
  `curl -X POST https://<service>.onrender.com/api/v1/feed/refresh -H "X-Ingest-Token: <token>"`.
- Every listing links back to its source, the feed is public (no login), and source names are shown, as the APIs'
  terms require. Don't gate the feed behind a signup.

## Optional
- Redis: set `REDIS_URL` (Upstash `rediss://…`) on Render to enable the job cache and rate limiter.
- CI deploy: the Deploy workflow is manual. To use it, add `RENDER_API_KEY` and
  `RENDER_SERVICE_ID` secrets and a `BACKEND_URL` variable to the repo's `production` environment.
